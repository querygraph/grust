# Resolve queries before graph semantic validation

Sail previously checked streamingness and the number of producers before resolving their queries. This masked missing tables and columns with flow-type or multiple-query errors. Spark 4.2.1 resolves its graph before semantic validation (`PipelineExecution.resolveGraph`, `DataflowGraph.validationFailure`). Keep identifier/target binding checks before resolution and defer graph semantics until queries resolve.

The native regression compares the underlying query error for a materialized view, a streaming destination fed by the same batch query, and multiple producers. The public regression compares terminal exception fields for materialized versus streaming destinations and checks that no target was published. Spark emits underlying source failures through events and raises an unresolved-pipeline exception; complete event/wrapper parity is still separate work.

Qualification: 205 Connect native tests, formatting, strict Clippy; 300 selected public cases and 67 upstream Python cases; ten paired public cases on Spark 4.2.1 and Sail (two precedence cases, six no-flow protocol cases and two streamingness scenarios). The two older streamingness scenarios now define their pipeline source; assertions are unchanged. The initial candidate exposed two incorrect missing-source fixtures and a temporary-view no-flow regression (296/300), retained here; the latter is fixed by retaining an empty schema until graph validation reports the no-flow error. The unchanged public tests fail on the preceding Sail binary, and the native regression fails on a test-only control commit with a real missing-table error masked by streamingness. This packet does not establish full Spark SDP conformance or implement all validation/error-event ordering.
