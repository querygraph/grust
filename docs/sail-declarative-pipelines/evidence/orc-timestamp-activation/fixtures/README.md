# Retained ORC timestamp fixtures

Three files were written by Spark 4.2.1; foreign_submicro was written by Apache ORC 2.3.0 Java using the Spark distribution jars. All four were read by Spark 4.2.1 during the earlier ORC reference collection. Original file bytes were checked against its validation.json SHA-256 manifest before copying. spark-reference.json preserves the selected source/read observations, generation SQL, file hashes and source provenance; ForeignSubmicro.java is the small foreign writer.

The original generator did not directly log the reader JVM's timezone ID. LA was initially inferred from the Spark writer stripe metadata and unchanged local process, and matched the foreign file's winter +8h read shift. A fresh reread now directly observes the JVM default ID/property, en-US FORMAT locale, oldmapping=false, Oracle Java20.0.2+9-78 and tzdb2023c. The explicit LA reader reproduces all four retained files in both UTC and LA SQL sessions; a separate explicit UTC reader produces different foreign timestamp values in both sessions. explicit-reader-reference.json retains these observed contexts and results, with source/script hashes. This requalifies the selected LA context without claiming to recover the original JVM's unlogged identity.

The UTC SQL fixture deliberately retains Spark's negative-epoch result: source LTZ -1 microsecond reads as +999999 microseconds; NTZ -1 is unchanged. The foreign UTC-writer file contains submicrosecond values and is read with microsecond truncation after reader-timezone conversion. Nested arrays, maps and structs distinguish null elements, null containers, empty containers and a valid struct with null fields.

No JVM is needed to run these Rust fixture tests. They exercise the controlled native reader plus logical bridge, not a registered Sail file source. Spark Connect toArrow labels LTZ as UTC in both SQL sessions; Sail's internal session/display labels are a separate representation policy. Tests assert the observed numeric values independently from that label policy. DST transitions, historical rebasing, TIMESTAMP_INSTANT and broader Spark/JVM configurations are outside this retained corpus.
