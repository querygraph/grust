## Rule applied

Audit 2's rule, with three readings made explicit, because classification of many rows depends on them.

1. **A union of tests may cover a row** when each Spark assertion has a named test, and a Rust validator test uses Spark's values. Handler:84, :113, :145, :233 and Multi 5 depend on this: Python pins the end-to-end effect, Rust pins `sqlState` and exact parameters.
2. **By-name projection.** Spark's `checkAnswer(spark.table(...))` pins the whole row. Python's by-name select of every column does not pin column count or order. It is accepted only where that shape is not the subject of the Spark test. Where the column in question was added by evolution, it is not accepted, and that is why TargetDurability 3 stays PARTIAL. Thirteen rows depend on this reading (listed below). Audit 2 made the same call implicitly, by calling them "metadata only".
3. **A `\S*` prefix on an identifier** is not a pinned parameter on its own. It is accepted only when another named test pins the qualification, and the plumbing between was read. Multi 5 depends on this.

Query context in `checkError` is treated as a diagnostic, as in audit 2.
