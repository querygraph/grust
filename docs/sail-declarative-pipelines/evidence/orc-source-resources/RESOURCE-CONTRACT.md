# ORC source resource contract — selected proposal

Read-only design audit, 2026-10-29. Sail baseline `27ab945aaa3046d05a1f4aeb1e651fddf11db927`; native ORC baseline `ec6baa46860fb3df95c23a72124e736c5334a418`; registry DataFusion 55.2.0 and bytes 1.12.1. No builds or repository changes by this reviewer. Root accepted the metadata defaults below on this checkpoint. Root's encoded-reader implementation is a separate incoming unit, reviewed below.

## Decision

Implement an ordinary Sail `FileSource`/`FileOpener` using the native async reader, one active native stripe per opened file and DataFusion's existing file scheduling. Bind the local runtime memory pool in both local construction and worker codec reconstruction. Account reader-owned encoded range buffers through their actual `Bytes` ownership. Apply explicit metadata output/depth limits, checked file/stripe/array arithmetic, and the existing session batch row count. Do not introduce a universal decoder allocator, process RSS promise, spilling, detached decode task, or a cumulative decoded-data-stream byte ceiling in this first source.

The guarantee is precise: requested encoded assembly bytes are admitted to the local pool before GET/allocation; reported Vec capacity is reconciled immediately after allocation and before copying the response. Successfully returned buffer capacity remains charged until its final owner drops. Metadata byte limits bound specified encoded/decoded byte counts, and depth limits bound recursive schema shape. These are not a total heap bound. They are stronger accounting for this ownership boundary than the existing format readers, without redefining Sail's general memory contract.

## Exact Sail options and derivation

Use positive-or-zero checked integer values; reject negative, overflowing, or non-integer input. Zero means a zero budget, not silently unlimited. Expose explicit overrides through the ORC read options and serialize the configured values with the source. Native generic defaults remain unchanged.

| Sail setting | Default | Effective value |
|---|---:|---|
| `max_encoded_metadata_bytes` | 67,108,864 bytes | min(configured value, finite local pool limit), otherwise configured value |
| `max_decoded_metadata_bytes` | 67,108,864 bytes | same derivation |
| `max_decoded_stripe_footer_bytes` | 67,108,864 bytes | same derivation |
| `max_schema_depth` | 64, root STRUCT = 0 | configured value |

These are configurable Sail operational defaults, not Spark schema-validity limits or ORC format maxima. They do not restrict timestamp/date/value domains. `MemoryLimit::Unknown` and `Infinite` retain the configured ceilings. Clamp byte values to the addressable `isize::MAX` bound before native allocation APIs. Do not read `pool.reserved()` to set these ceilings, divide by partition count, or depend on current concurrency; pool admission itself remains dynamic. The worker uses its own pool, not a serialized pool or the driver's available-memory snapshot. A smaller worker pool can fail a query for resources as other pool consumers do.

The file-tail encoded limit counts combined encoded footer + metadata, as the existing native API documents. Its initial tail read is at most 16 KiB and may include file data, so a smaller limit can still cause that initial read before the tail's declared metadata length is checked. The decoded tail budget is shared by footer and file metadata. Stripe-footer budget is per started stripe. There is no added encoded-stripe-size or total-decoded-column-stream cap: all selected encoded ranges still face checked file bounds and pool admission. With an unbounded pool, encoded stripe allocations are correspondingly unbounded except for addressability/file extent; do not describe the three metadata limits as a bound on those ranges.

## Ownership and cancellation

`OrcObjectReader::new(store, meta, pool)` should require the pool because the reader has no existing production callers to preserve; tests use an explicit unbounded pool where memory admission is irrelevant. Each nonempty range owns a nonspillable `MemoryReservation`. Reserve requested length before `get_opts`, validate returned identity/range, allocate via `try_reserve_exact`, reconcile capacity, consume exact-length chunks, then return `Bytes::from_owner(ReservedRange { buffer, reservation })`. Put the Vec field before the reservation so destruction releases memory before its charge. A range failure must preserve the underlying error cause and drop both. Do not release the reservation at function return or when the reader itself drops while returned bytes remain live.

The owner does not charge object-store SDK response chunks, allocator metadata/rounding beyond reported capacity, native tail coalescing, codec scratch/history, protobuf allocations, dictionaries, or Arrow batches. A response chunk can coexist with the assembled range. `Bytes::from_owner` conversions to mutable bytes make a copy rather than transferring this owner's accounting. Native metadata currently coalesces tail + prefix into a new `BytesMut`; do not claim this temporary copy is charged by the source owner.

Keep native decoding directly owned by the returned async stream, with no extra producer queue. Dropping a pending open/read or stream drops its futures, retained ranges, decoder, and reservations; it does not revoke Arrow batches already handed to downstream operators. I/O futures can be cancelled at await boundaries. Native footer parsing, dictionary construction, and one batch decode are synchronous and are not preemptible mid-call. Batch row count is a scheduling/row-size parameter, not a bounded cancellation latency or output-byte cap. Do not add `spawn_blocking` as if dropping its handle cancelled running work. First source tests should prove drop/release and no further source-driven requests after dropping pending work, not assert hard elapsed-time cancellation bounds or remote-server cancellation.

## Native allocation audit and smallest changes

1. **File tail: existing APIs suffice.** Call `read_metadata_async_with_options` and configure all three fields before schema conversion, including projected-out types. Keep full metadata validation before projection. Tail prefix coalescing and protobuf materialization are bounded indirectly by the configured byte counts, but their heap multipliers are not accounted. No new native file-metadata API is required.
2. **Encoded stripe and stream bounds: checked arithmetic, no allocator API.** Before opening native stripes, Sail can validate each applicable declared stripe's `offset + index_length + data_length + footer_length` using checked u64 additions against the immutable listed object size, and checked row-count/addressability conversion. This prevents native `footer_offset()` overflow on the source path today. Native should separately harden its own started-stripe path: compute footer offset with checked additions, validate each stream's checked end does not exceed the declared index+data section before reading it, and validate usize row counts. Do not demand an unverified exact sum equality or padding policy. This fixes malformed arithmetic/range access, not a new limit on legitimate stripe sizes.
3. **Decoded stripe footer: one genuinely required public extension.** Add `ArrowReaderBuilder::with_max_decoded_stripe_footer_bytes(usize)` backed by `Option<usize>` defaulting to `None`. Carry it through sync/async cursors into private stripe construction and call `Decompressor::new_with_limit` in `deserialize_stripe_footer`. Old constructors/defaults remain unchanged; public direct `Stripe::new*` keeps its current unrestricted behavior. Native tests must cover sync/async and exact/over/zero budgets with compressed and uncompressed footers, multiple blocks, and original blocks. This needs no DataFusion dependency and no generic allocator callback. Keep the builder option independent of timestamp options.
4. **Intrinsic value-length safety: no new public policy/API.** Native list/map/string decoders currently sum signed lengths unchecked and cast to usize. Validate nonnegative lengths, checked totals, i32 offsets for existing List/Map/Utf8/Binary output types, usize/isize addressability and checked element-size multiplication before allocating child arrays/buffers. Include skip paths. Dictionary sizes also originate in the footer and allocate at decoder construction; check addressable allocation arithmetic and use fallible reserve where practical. These checks remove integer/capacity panics and intrinsically unrepresentable arrays; they do not make a valid huge value inexpensive or guarantee recovery from every allocator OOM. Keep conversion to a general memory-aware Arrow allocator outside the selected source unit.
5. **Data decoding stays incremental.** Existing compression guard rejects declared blocks outside `(0, 2^23)` and enforces block decoded output, with an optional limit+1 overflow probe for streaming codecs and bounded zstd history. Do not apply a 64 MiB lifetime decoded limit to column streams: a valid long stripe can yield many batches while retaining only block scratch and dictionary state. Native retains encoded streams across the stripe and dictionaries across batches; one block's old and new buffers can briefly coexist. The exact number of live buffers depends on projected columns and decoders. Variable-length data and nested child counts mean one row can still be large.
6. **First source does not enable native predicate pruning.** Optional row-index/bloom-filter parsing currently uses unbounded read_to_end. Leave it uninvoked in this unit; retain unknown converted timestamp statistics and normal downstream filtering. A later pruning unit must bound its metadata outputs and preserve error/result semantics. Merely having the index bytes retained in the stripe is not evidence that index decoding is bounded.

## Human-reviewable units and acceptance tests

1. **Sail encoded buffer owner** (source-local, root's current draft): required local pool, reservation owner, existing identity behavior preserved. Tests: pool refusal before GET; zero-byte zero-pool read; clones/slices and reader-drop survival; aggregate live ranges; response/identity/precondition errors; pending-body cancellation; error-cause preservation. Optional pending-GET cancellation strengthens the same lifetime boundary. Test actual reservation counts, not just returned bytes.
2. **Native footer budget**: only builder plumbing + sync/async stripe footer use + focused budget tests. Default API regression suite unchanged. Separately vendor the qualified native change.
3. **Native checked stripe/length arithmetic**: focused malformed tiny fixtures for overflow, negative length, i32 offset overflow, truncated payload; exercise direct values, nested children, dictionary setup, and skipping without allocating attacker-declared huge buffers. Verify small valid values remain identical. This is an intrinsic error-handling fix; do not combine it with optional pruning.
4. **Sail options/source integration**: exact defaults and overrides; finite/unknown/unbounded pool derivation; tiny budgets; full-schema validation before projection; source-local stripe preflight; codec roundtrip of configuration and rebinding to the worker's pool. Use actual DataFusion FileStream and batch sizes. Confirm normal multi-stripe data over 64 MiB decoded in aggregate is not rejected by a mistakenly cumulative data-stream cap.
5. **Cancellation/lifetime integration**: counting store holds GET/body pending; dropping opener/scan releases charges and makes no new requests; completed stream releases current stripe while retained downstream batches remain valid. No wall-clock cancellation promise.
