## Current guarantees and gaps

1. **Manager shutdown still omits live local runners.** `crates/sail-session/src/session_manager/actor/core.rs:113–136` stops immediately on the Shutdown message, drains only the driver registry, joins child actors, stops the gateway, and sends a unit acknowledgement. Local runners have no child driver (`session_factory/job_runner.rs:101–104`), so their stop path is never invoked by manager-wide shutdown. The newly fallible local stop is implemented in `crates/sail-execution/src/job_runner/local.rs:155–220`; it seals admission, cancels all snapshotted jobs, awaits reports, and retains typed failures. The manager must actually call it.

2. **In-flight deletions have no manager-owned completion record.** `session_manager/actor/handler.rs:373–390` clones JobService, checkpoint registry and runtime into `ctx.spawn`; errors are only logged. Idle and explicit deletion immediately set Deleted and remove the driver (`269–330`). The helper at `actor/cleanup.rs:7–16` correctly awaits `runner.stop()?` before invoking checkpoint cleanup. That correct ordering does not make the surrounding spawned task durable or observable.

3. **Creating sessions also need ownership.** `ServerSessionState::Creating` stores only driver ID and waiters (`session_manager/session.rs:11–21`). After synchronous factory creation, the context is captured in an activation task or `CompleteSessionCreation` message (`actor/handler.rs:153–178`). A sweep of Running sessions misses a successfully created local context whose completion message is queued behind Shutdown. Capture an independent context/JobService cleanup owner before this handoff. No new admission can interleave inside the synchronous factory call, but Shutdown can interleave before its completion message is processed.

4. **ActorContext tasks are abort-on-drop, not joined shutdown work.** `crates/sail-common/src/actor.rs:103–113,133–155` uses a `JoinSet<()>` whose pending tasks are aborted on context destruction; `reap` only removes completed tasks and logs errors. This set mixes cleanup, idle timers (`send_with_delay`, lines 174–180), self-sends, and activation work. `ctx.children_mut().join()` joins a different set. A blanket `join_tasks()` would wait for arbitrary idle timeouts and tasks that need manager replies; it is not a safe fix.

5. **Mailbox close, stop-hook completion and actor join are distinct.** `ActorRunner::run` closes its receiver at `actor.rs:436–440`, then awaits the stop hook at 441, reaps at 442, and only afterward drops the context/receiver. `ActorHandle::send` merely enqueues (`354–365`). `ActorSystem::join` waits for actor futures but logs join errors and returns unit (`274–285`). Neither a closed mailbox nor a successful enqueue proves cleanup, hook completion or a successful join. The existing driver wrapper incorrectly treats failed send/closed reply as successful shutdown (`crates/sail-execution/src/driver/registry.rs:53–72`); retain the explicit cluster limitation rather than using this as a new reliable completion primitive.

6. **The current stop-hook placement admits a mailbox/gateway deadlock.** `SessionDriverRegistry::get` sends GetDriver and awaits its oneshot (`session_manager/actor/core.rs:21–31`). Consider GetDriver already enqueued behind Shutdown: the receiver remains alive, retaining the reply sender, while the actor no longer processes messages. An active gateway request waits for that reply. The manager stop hook awaits graceful gateway termination (`core.rs:129–131`), whose server task is joined at `crates/sail-execution/src/driver/gateway.rs:169–175`; `sail-common/src/server/builder.rs:121–123` uses tonic graceful shutdown. The queued reply is released only after the hook returns. This is a source-derived interleaving, not a reproduced runtime failure. Late creation/deletion completion messages present the same general risk if their acknowledgement becomes part of cleanup.

## Smallest coherent manager-specific design

Keep this in `sail-session` first. The existing actor framework can host a manager closing phase; a generic actor lifecycle rewrite is not required.

**Separate ownership from notification.** Introduce one per-session cleanup record that owns the JobService/context, optional checkpoint registry, runtime and an immutable shared result. Install it before launching deletion work or handing a newly created context to a completion task. All deletion callers and manager shutdown observe the same cleanup operation; a dropped RPC receiver is only a dropped observer. Do not launch two checkpoint deletions for explicit-delete/shutdown races. Reuse `stop_and_clean_checkpoints` for the actual ordering, and preserve the difference between runner failure and checkpoint cleanup failure: `RemoteCheckpointRegistry::cleanup_session` seals and clears even when storage deletion fails (`crates/sail-cache/src/remote_checkpoint.rs:117–140`).

The record can be driven by an actor-owned task while the manager is alive, provided normal shutdown explicitly waits for that record before allowing actor exit. Its terminal result must be directly observable, without waiting for the manager to process a completion message. A shared future can be retained/polled by a later shutdown waiter, or an independently driven task can publish an immutable watch result with an interruption guard. Choose one ownership mechanism, not overlapping forwarding tasks. `ManagedStreamControl::completion` demonstrates observer cancellation and immutable watch-report semantics (`crates/sail-common-datafusion/src/managed_stream.rs:85–100`), but it is not itself an actor join primitive. Notifications to update session status may follow publication; they must not own the only resources or be prerequisite to actual cleanup completion.

**Add Open → Closing → terminal manager state.** The first accepted Shutdown seals session admission and starts a coordinator, but returns `ActorAction::Continue`. While Closing:

- reject new get/create requests and do not revive an already-closing session;
- accept repeat shutdown observers and deletion requests by attaching them to retained records;
- continue serving GetDriver and disposing/recording late creation completions;
- do not schedule new idle probes; pending timers need not be drained;
- start/drive cleanup for every owned local context and every already-started deletion, without serially awaiting the first blocked session before requesting other stops.

The coordinator awaits all selected cleanup records and the required driver/child/gateway teardown while the manager can still process lifecycle messages. A concrete way to keep the existing child ownership model is to move the child `ActorSystem` into the coordinator with `mem::take(ctx.children_mut())` once admission is sealed; retain the driver's lookup handles in the actor until the gateway no longer needs them. Stop child drivers, join their owned actor futures, and only then stop/join the gateway, preserving the current documented gateway ordering. This requires testing the ownership transfer, not adding a general task-drain policy. If child/gateway teardown remains in the stop hook instead, prove that none of it can await this actor's mailbox; current code does not satisfy that proof.

Only after the coordinator's owned work reaches its recorded disposition should an internal completion message let the actor return Stop. Publish the manager's immutable typed completion from its final stop path after the intended cleanup barrier, rather than as an early acceptance acknowledgement. A completion guard/channel-closure error must turn coordinator/actor interruption into an explicit failure, not leave observers waiting forever or treat mailbox closure as success.

**Share the terminal result outside the mailbox.** Construct manager-wide completion state when `SessionManager::try_new` creates the actor (`session_manager/mod.rs:37–45`), and clone its read handle with `SessionManager`. `shutdown()` should request idempotent closure and await this shared result; repeat/concurrent callers must see the same result even after the mailbox closes. Avoid setting a one-shot "started" flag before an awaitable send with no cancellation rollback: a caller canceled before enqueue would otherwise strand the state. A canceled request before acceptance is not a completed shutdown request; after acceptance, cleanup must not depend on that requester.

**Do not discard uncertain ownership on Err.** `JobRunner::stop` returns only `Result<()>`, not a drain qualification (`crates/sail-common-datafusion/src/session/job.rs:22–24`). A manager cannot infer from an Err that every underlying resource was drained. Retain failed cleanup records/owners in shared state, rather than converting them to an ownerless Deleted marker and dropping the actor's last service reference. Decide separately whether a repeated API call observes the immutable failure or explicitly retries an owned operation; do not silently repeat destructive checkpoint cleanup. Survival of a canceled observer assumes the actor-system owner and Tokio runtime remain alive. Forced ActorSystem/runtime destruction is a separate interruption boundary, not a shutdown success guarantee.

An alternative very small actor-framework change would drop buffered mailbox messages before awaiting stop hooks, rather than just close the receiver. That can release the specific queued-oneshot deadlock, but it changes every actor's queue-disposal timing, does not preserve queued contexts by itself, and does not keep the gateway's registry available. It is not a substitute for the manager ownership work above and should only be considered as a separately reviewed prerequisite.

## Typed results and caller changes

Use the current typed error path: `SessionError::DataFusionError` (`crates/sail-session/src/error.rs:10–14`). Wrap each session failure with `DataFusionError::Context` if session identity is needed, combine siblings with `DataFusionError::Collection`, and return repeated observations through `DataFusionError::Shared(Arc<...>)`. Existing `CommonErrorCause` unwraps Context/Shared and scans Collection for a nonretryable cause (`crates/sail-common-datafusion/src/error.rs:167–197`); CommitStateUnknown is explicitly nonretryable (119–122,210–211). Do not stringify cleanup errors into `SessionError::internal`. Await all siblings and aggregate, rather than `try_join` or an early `?` that drops their futures. Catch a cleanup task panic at the owned-operation boundary and publish an explicit failure while preserving the other tasks' progress.

The following caller adjustments are necessary for the stronger manager result:

- `crates/sail-spark-connect/src/entrypoint.rs:70–72` and `crates/sail-flight/src/entrypoint.rs:38–40` currently use `shutdown().await?` before `system.join().await`. Store the shutdown result, **always perform the join**, then return/aggregate the server and shutdown outcomes. Otherwise any newly surfaced cleanup error skips the join and drops the actor system. Preserve both failures if transport and cleanup fail.
- Both entrypoints currently await transport graceful completion before initiating manager shutdown (`Spark 63–71`, `Flight 33–39`). An active response whose termination requires runner stop can prevent reaching manager shutdown. On the external shutdown signal, arrange manager stop concurrently with transport graceful draining, without starting a second cleanup owner. Also initiate manager cleanup when the transport exits with an error. This is a source-derived liveness hazard requiring a focused active-stream test.
- Python wrappers signal and join their server thread with the GIL released (`crates/sail-python/src/spark/server.rs:24–37,111–114,136–149`; Flight has the analogous `wait/run_blocking` path). They already surface an error, although they format it at the Python boundary. No Python lifecycle rewrite is needed for the local manager improvement.
- Canceling the *whole* serve future drops the ActorSystem it owns (`Spark entrypoint.rs:49`, `Flight entrypoint.rs:23`), aborting actor tasks. Do not equate cancellation of a shutdown observer with destruction of this owner. If the public contract must survive a canceled serve future as well, the server owner must move to a separately retained task/handle; that is an additional explicit unit.

`ActorSystem::join` and gateway.stop currently swallow join/server failures. A local-manager unit can report typed local cleanup failures while naming these pre-existing cluster limitations. If it claims typed actor/gateway aggregate failure reporting too, add a narrow fallible join/stop path. Remember that prior `ActorSystem::reap` already discards join errors (`actor.rs:288–296`); merely making the final join return Result cannot recover those. Retain relevant earlier join failures or deliberately limit the guarantee. Driver/worker cleanup qualification remains a separate design phase.

## Deterministic fault tests

Use oneshot/barrier gates and observation channels; timeouts should only bound failed tests, not establish ordering.

1. **Live local session:** keep an admitted stream unpolled and a resource supervisor blocked. Start manager shutdown; verify runner stop/cancellation starts, new admission fails, checkpoint descriptors remain, and neither manager completion nor actor-system join finishes before resource release.
2. **Two sessions, first blocked/failing:** gate session A's stop and observe session B's stop begins before releasing A. Let A fail with typed CommitStateUnknown and B finish; verify both are awaited, B cleanup succeeds, A checkpoint cleanup was never invoked, and the final collection retains the nonretryable cause.
3. **Explicit/idle deletion overlap:** begin deletion, hold it before resource drain, then initiate shutdown. Verify one cleanup operation, no duplicate namespace deletion, no early terminal result, and no loss when the deletion requester is dropped.
4. **Concurrent/repeated shutdown callers:** cancel the first observer after acceptance, keep a second, then add another after mailbox closure. All surviving observers receive the same result. Separately cancel a request while its bounded send is blocked; a later caller must still be able to initiate shutdown.
5. **Creating context handoff:** hold CompleteSessionCreation after context construction, enqueue Shutdown first, then release completion. Verify the context is retained/stopped, no successful new-session response is delivered during Closing, and no context is owned solely by an abandoned mailbox message.
6. **Mailbox/gateway cycle:** enqueue a GetDriver request behind Shutdown and hold a fake gateway's termination on that reply. Verify the closing actor serves/rejects the request explicitly and shuts down; do not accept a timeout-induced abort as success. Fill the bounded mailbox with lifecycle messages to cover completion-send backpressure.
7. **Do not join unrelated ActorContext tasks:** leave an idle probe scheduled at a very long timeout. Cleanup-qualified manager shutdown must finish without waiting for that timer, while a gated deletion task is still awaited.
8. **Panic/interruption:** panic inside one cleanup operation after the record is installed; other sessions still stop and observers receive a typed failure. Interrupt the coordinator/actor before publishing success and verify no false Ok/no hanging completion; state clearly that forced runtime destruction cannot guarantee eventual cleanup.
9. **Entrypoint error ordering:** inject a cleanup Err and verify actor-system join still runs; combine transport and cleanup errors and verify both remain available. With an active streaming response, send the transport shutdown signal and verify runner stop begins before waiting for that response to finish.
10. **Mailbox versus terminal hook:** hold an actor stop hook at a barrier, observe its send channel close, and assert no shutdown completion/join claim until the hook is released. If a fallible ActorSystem join path is added, include an actor that panics before an ordinary `reap` and confirm the later shutdown report retains that failure.

This checkpoint proposes an ownership/liveness boundary. It does not establish a passing manager-wide shutdown implementation or extend the current local runner tests into whole-server, cluster, streaming, Iggy, or CDC coverage.
