1. **Post-resolution CDC target checks currently run before source analysis.** Sail `crates/sail-spark-connect/src/pipelines/analysis.rs:83–112` calls `graph.validate()` before resolving any flow. The new `graph.rs:399` invokes `autocdc/mod.rs:241–256`, which rejects a temporary-view target from the raw definition. Spark `sql/pipelines/src/main/scala/org/apache/spark/sql/pipelines/graph/DataflowGraph.scala:198–207` first calls `validateSuccessfulFlowAnalysis`, then schema/topology/multiquery checks, and only later streamingness validation. `GraphValidations.scala:97–104,153–167` checks the temporary-view case only on a successfully resolved `AutoCdcMergeFlow`; `GraphValidations.scala:288–329` surfaces resolution failures first. This also applies to the new early CDC multiflow check: it can mask a source-resolution failure. A known deferred schema-validation unit does not justify eagerly selecting a later target error.

   Suggested regression: register a valid unrelated persistent output, then a CDC flow reading a nonexistent source and targeting a temporary view. Definition should register, but dry run should surface the unresolved input through the pipeline's normal error wrapper before `AUTOCDC_RELATION_FOR_TEMPORARY_VIEW`. Repeat with a CDC multiflow target and an invalid source. The current new Rust graph test at `autocdc/tests/graph.rs:85–101` has an unresolved `events` fixture and directly calls `validate`, so it cannot establish Spark's public phase ordering.

2. **The sink rejection is an execution-planning check, not a dry-run graph check.** Sail `autocdc/mod.rs:258–263` adds `Unsupported destination type: SinkImpl` to the same early validation path. Spark's check is at `sql/pipelines/src/main/scala/org/apache/spark/sql/pipelines/graph/FlowPlanner.scala:80–97,111–115`. It is invoked by `GraphExecution.scala:79–83` when planning/starting a flow. In contrast, `PipelineExecution.scala:87–93,111–114` shows that dry run only resolves and validates the graph and never invokes `FlowPlanner`.

   Suggested regression: a resolvable, schema-valid CDC source and sink destination plus any required normal pipeline output. The dry run must not throw this execution-planning error. Keep Sail's existing incremental-execution boundary for real execution; defer/remove the new sink validation arm rather than claiming this earlier rejection mirrors Spark. `autocdc/tests/graph.rs:169–179` currently asserts the shifted phase.

3. **CDC multiflow precedence is global in Spark, but per output in Sail.** Sail `graph.rs:383–404` iterates output registration order and performs `validate_target` followed immediately by the materialized-view multiflow check. An earlier MV with multiple batch flows wins over a later CDC target with multiple flows. Spark `sql/pipelines/src/main/scala/org/apache/spark/sql/pipelines/graph/GraphValidations.scala:35–75` searches all multiflow destinations for Auto CDC first, before searching any destination for non-streaming/MV multiflow. Merely placing `validate_target` before the adjacent MV branch does not preserve that contract.

   Suggested regression: all inputs resolve; register a materialized view with two valid batch flows first and a streaming target with one CDC flow plus another flow second. Expect `AUTOCDC_MULTIPLE_FLOWS_TO_TARGET` in both registration orders. Keep source-analysis precedence from finding 1 when organizing the passes.

4. **Four-part CDC sources are not rejected at definition time.** Sail `autocdc/mod.rs:138–145` uses `graph::parse_name` (`graph.rs:13–15`), which only parses an object name and normalizes it. It never restricts the source to the one-to-three parts accepted by Spark. Spark `sql/connect/server/src/main/scala/org/apache/spark/sql/connect/pipelines/PipelinesHandler.scala:444–448` calls `GraphIdentifierManager.parseTableIdentifier`; `sql/pipelines/src/main/scala/org/apache/spark/sql/pipelines/graph/GraphIdentifierManager.scala:35–36,262–275` throws `UnsupportedOperationException` for four or more parts before processing keys. Sail instead registers such a source or lets a later argument error win.

   Suggested regressions: source `a.b.c.d` with valid arguments fails during DefineFlow; source `a.b.c.d` plus empty keys or invalid key expression still reports the source-identifier failure. A missing sequence expression must retain its existing earlier precedence. A quoted single-part source containing dots remains valid.

5. **The reused proto expression fallback bypasses the CDC identifier contract.** Sail `autocdc/mod.rs:187–193` accepts every resulting `spec::Expr::UnresolvedAttribute` with one name part. The generic converter at `crates/sail-spark-connect/src/proto/expression.rs:40–51` falls back to one raw identifier when SQL identifier parsing fails. Consequently malformed dot/backtick syntax can become an accepted CDC key/list name, and non-SQL multipart names can lose their parts. This helper predates the commit, but its behavior does not implement the new CDC validation contract.

   Spark's call chain is `sql/connect/server/src/main/scala/org/apache/spark/sql/connect/pipelines/PipelinesHandler.scala:452–461` → `sql/connect/server/src/main/scala/org/apache/spark/sql/connect/planner/SparkConnectPlanner.scala:1979–1988` → `sql/catalyst/src/main/scala/org/apache/spark/sql/catalyst/analysis/unresolved.scala:351–357` → `sql/api/src/main/scala/org/apache/spark/sql/catalyst/util/AttributeNameParser.scala:23–64`. That parser preserves arbitrary characters within unquoted parts, splits dots, and rejects malformed dots/backticks. `sql/api/src/main/scala/org/apache/spark/sql/errors/DataTypeErrors.scala:147–150` supplies `INVALID_ATTRIBUTE_NAME_SYNTAX`.

   Suggested regressions through raw UnresolvedAttribute/Connect `col`: `a..b` and an unclosed backtick fail with `INVALID_ATTRIBUTE_NAME_SYNTAX`; `a b.c` reaches `AUTOCDC_MULTIPART_COLUMN_IDENTIFIER` with two parts; quoted `` `a..b` `` remains a valid single name. Exercise keys and each column-list arm. Correct the narrowly applicable parsing path or offer a separately reviewed general converter repair; do not silently alter Sail's general resolver contract inside the CDC unit.
