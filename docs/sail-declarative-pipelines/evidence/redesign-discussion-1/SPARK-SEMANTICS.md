## Verified pipeline execution behavior

**Available now is the pipeline trigger.** `PipelineExecution` constructs `TriggeredGraphExecution`, whose `streamTrigger` returns `Trigger.AvailableNow()`. `StartRun` exposes refresh selections, dry validation and storage, without a continuous-mode field. These facts support saying that this pinned pipeline implementation runs streaming flows with available now. They do not describe every Structured Streaming trigger. Sources: [PipelineExecution.scala:46](https://github.com/apache/spark/blob/617618396087429b5627a86ce933bb0f5d6645cb/sql/pipelines/src/main/scala/org/apache/spark/sql/pipelines/graph/PipelineExecution.scala#L46), [TriggeredGraphExecution.scala:76](https://github.com/apache/spark/blob/617618396087429b5627a86ce933bb0f5d6645cb/sql/pipelines/src/main/scala/org/apache/spark/sql/pipelines/graph/TriggeredGraphExecution.scala#L76), [pipelines.proto:231](https://github.com/apache/spark/blob/617618396087429b5627a86ce933bb0f5d6645cb/sql/connect/common/src/main/protobuf/spark/connect/pipelines.proto#L231).

**Available now does not imply one batch or one checkpoint.** The source interface explicitly allows multiple batches. It asks the source to capture a target offset when the query starts and prevents later offsets from exceeding it, with a documented exception for the first uncommitted batch after restart. Do not claim one atomically captured position across the entire pipeline graph, or derive a single-final-checkpoint requirement from Spark. Source: [SupportsTriggerAvailableNow.java:23](https://github.com/apache/spark/blob/617618396087429b5627a86ce933bb0f5d6645cb/sql/catalyst/src/main/java/org/apache/spark/sql/connector/read/streaming/SupportsTriggerAvailableNow.java#L23).

## Verified change capture behavior

**Validation precedes reduction and both merges.** The handler passes the original batch to `validateMicrobatch`, then reconciles it, then merges into the auxiliary table and the target in that order. Validation scans every original row for null sequence values and null values in each declared key column. It rejects non-orderable sequence types. The orderability implementation rejects map types and recursively checks array elements and struct fields. Sources: [Scd1ForeachBatchHandler.scala:39](https://github.com/apache/spark/blob/617618396087429b5627a86ce933bb0f5d6645cb/sql/pipelines/src/main/scala/org/apache/spark/sql/pipelines/autocdc/Scd1ForeachBatchHandler.scala#L39), [ScdBatchValidator.scala:45](https://github.com/apache/spark/blob/617618396087429b5627a86ce933bb0f5d6645cb/sql/pipelines/src/main/scala/org/apache/spark/sql/pipelines/autocdc/ScdBatchValidator.scala#L45), [OrderUtils.scala:26](https://github.com/apache/spark/blob/617618396087429b5627a86ce933bb0f5d6645cb/sql/api/src/main/scala/org/apache/spark/sql/catalyst/expressions/OrderUtils.scala#L26).

For a composite key consisting of several declared columns, each column is checked. The validator does not recursively reject every null field inside an otherwise non-null struct-valued key or sequence. Wording about a “null part of a composite key” should mean a null declared key column, unless a stronger rule is separately chosen and verified.

**Equal-sequence winners within a batch are undefined.** The processor groups by the keys and selects the whole row with `max_by`. Its contract explicitly declares equal-key, equal-sequence selection nondeterministic and undefined. The aggregate implementation selects the new or right operand when the sequence comparison ties, so input and merge order matter. A fixed source-position tie rule would be a Sail decision. Sources: [Scd1BatchProcessor.scala:80](https://github.com/apache/spark/blob/617618396087429b5627a86ce933bb0f5d6645cb/sql/pipelines/src/main/scala/org/apache/spark/sql/pipelines/autocdc/Scd1BatchProcessor.scala#L80), [MaxByAndMinBy.scala:69](https://github.com/apache/spark/blob/617618396087429b5627a86ce933bb0f5d6645cb/sql/catalyst/src/main/scala/org/apache/spark/sql/catalyst/expressions/aggregate/MaxByAndMinBy.scala#L69).

**Delete classification precedes column selection.** A delete-condition value of true creates a delete; false or null creates an upsert. The processor then projects the user-selected columns while retaining operational metadata. Sources: [Scd1BatchProcessor.scala:113](https://github.com/apache/spark/blob/617618396087429b5627a86ce933bb0f5d6645cb/sql/pipelines/src/main/scala/org/apache/spark/sql/pipelines/autocdc/Scd1BatchProcessor.scala#L113), [Scd1BatchProcessor.scala:164](https://github.com/apache/spark/blob/617618396087429b5627a86ce933bb0f5d6645cb/sql/pipelines/src/main/scala/org/apache/spark/sql/pipelines/autocdc/Scd1BatchProcessor.scala#L164).

**Tombstones filter only strictly older events.** After reduction, a left anti-join drops a row if an auxiliary tombstone for the same key has a strictly greater delete sequence. Equal-sequence events survive this filter. In the auxiliary merge, a strictly newer delete advances a tombstone, a surviving upsert at or above the tombstone sequence removes it, and a new delete creates a tombstone. Sources: [Scd1BatchProcessor.scala:220](https://github.com/apache/spark/blob/617618396087429b5627a86ce933bb0f5d6645cb/sql/pipelines/src/main/scala/org/apache/spark/sql/pipelines/autocdc/Scd1BatchProcessor.scala#L220), [Scd1BatchProcessor.scala:265](https://github.com/apache/spark/blob/617618396087429b5627a86ce933bb0f5d6645cb/sql/pipelines/src/main/scala/org/apache/spark/sql/pipelines/autocdc/Scd1BatchProcessor.scala#L265).

**Target comparisons distinguish upserts and deletes.** An upsert updates an existing target row at an equal or greater sequence. A delete removes it only at a strictly greater sequence. A delete for an absent target key is not inserted into the target. Therefore, a delete older than a live target upsert can leave that row intact while creating an auxiliary tombstone. A delete discarded by the same-batch reduction never reaches either merge. Equal-sequence priority in these target comparisons must not be confused with the undefined tie during reduction. Source: [Scd1BatchProcessor.scala:329](https://github.com/apache/spark/blob/617618396087429b5627a86ce933bb0f5d6645cb/sql/pipelines/src/main/scala/org/apache/spark/sql/pipelines/autocdc/Scd1BatchProcessor.scala#L329).

**Two sequential merges are not a Spark checkpoint transaction-tag protocol.** The handler invokes auxiliary then target merge and describes replay safety through sequence inequalities. It passes `batchId` into validation, but these merge calls do not use it as an application transaction tag. The inspected method does not seal or persist the reconciled rows. Sail's sealed artifacts, effect receipts and checkpoint tags are additional recovery mechanisms that require their own design and evidence. Source: [Scd1ForeachBatchHandler.scala:33](https://github.com/apache/spark/blob/617618396087429b5627a86ce933bb0f5d6645cb/sql/pipelines/src/main/scala/org/apache/spark/sql/pipelines/autocdc/Scd1ForeachBatchHandler.scala#L33).

**Key drift compares a resolver-aware set of names and types.** Creation records the resolved key names on the auxiliary table. Subsequent setup checks key arity, name matching under the session resolver, and matching types by name. A change of declaration order alone is accepted; schema nullability and metadata changes are tolerated. Runtime null key values remain invalid. Sources: [FlowExecution.scala:419](https://github.com/apache/spark/blob/617618396087429b5627a86ce933bb0f5d6645cb/sql/pipelines/src/main/scala/org/apache/spark/sql/pipelines/graph/FlowExecution.scala#L419), [FlowExecution.scala:514](https://github.com/apache/spark/blob/617618396087429b5627a86ce933bb0f5d6645cb/sql/pipelines/src/main/scala/org/apache/spark/sql/pipelines/graph/FlowExecution.scala#L514), [FlowExecution.scala:623](https://github.com/apache/spark/blob/617618396087429b5627a86ce933bb0f5d6645cb/sql/pipelines/src/main/scala/org/apache/spark/sql/pipelines/graph/FlowExecution.scala#L623).

**Full refresh resets table and checkpoint generations.** Before graph execution, Spark rolls the selected flows' checkpoint directories. Dataset materialization truncates the existing target, drops its auxiliary table, and uses the current output schema instead of merging it with the old schema. The auxiliary table is then recreated with current keys. These paths do not establish that an arbitrary source restarts at its absolute historical origin or refuses a lost origin: fresh-start source options and retention behavior remain connector-specific. Sources: [PipelineExecution.scala:46](https://github.com/apache/spark/blob/617618396087429b5627a86ce933bb0f5d6645cb/sql/pipelines/src/main/scala/org/apache/spark/sql/pipelines/graph/PipelineExecution.scala#L46), [State.scala:71](https://github.com/apache/spark/blob/617618396087429b5627a86ce933bb0f5d6645cb/sql/pipelines/src/main/scala/org/apache/spark/sql/pipelines/graph/State.scala#L71), [DatasetManager.scala:301](https://github.com/apache/spark/blob/617618396087429b5627a86ce933bb0f5d6645cb/sql/pipelines/src/main/scala/org/apache/spark/sql/pipelines/graph/DatasetManager.scala#L301).

**The target must support row-level operations.** Flow construction checks `SupportsRowLevelOperations` and raises `AUTOCDC_TARGET_DOES_NOT_SUPPORT_MERGE` otherwise. The source test covers a non-merge-compatible Parquet target. This supports a capability-based refusal; it is not a fresh runtime test of every Hive or lakehouse provider. Sources: [FlowExecution.scala:473](https://github.com/apache/spark/blob/617618396087429b5627a86ce933bb0f5d6645cb/sql/pipelines/src/main/scala/org/apache/spark/sql/pipelines/graph/FlowExecution.scala#L473), [AutoCdcScd1SinglePipelineSuite.scala:169](https://github.com/apache/spark/blob/617618396087429b5627a86ce933bb0f5d6645cb/sql/pipelines/src/test/scala/org/apache/spark/sql/pipelines/graph/AutoCdcScd1SinglePipelineSuite.scala#L169).

## Verified watermark behavior and proposed differences

The watermark execution node measures event time in milliseconds. The tracker advances each watermark from maximum observed event time minus the configured delay. It supports minimum as the default global policy and also a maximum policy. Sources: [EventTimeWatermarkExec.scala:90](https://github.com/apache/spark/blob/617618396087429b5627a86ce933bb0f5d6645cb/sql/core/src/main/scala/org/apache/spark/sql/execution/streaming/operators/stateful/EventTimeWatermarkExec.scala#L90), [WatermarkTracker.scala:41](https://github.com/apache/spark/blob/617618396087429b5627a86ce933bb0f5d6645cb/sql/core/src/main/scala/org/apache/spark/sql/execution/streaming/runtime/WatermarkTracker.scala#L41), [WatermarkTracker.scala:106](https://github.com/apache/spark/blob/617618396087429b5627a86ce933bb0f5d6645cb/sql/core/src/main/scala/org/apache/spark/sql/execution/streaming/runtime/WatermarkTracker.scala#L106).

Microbatch metadata receives the current tracked watermark before execution; the tracker updates after execution. Stateful operators distinguish the previous batch's eviction watermark used for late-event filtering from the current watermark used for state eviction. Their window predicate compares the window end at or below the watermark. Sources: [MicroBatchExecution.scala:1004](https://github.com/apache/spark/blob/617618396087429b5627a86ce933bb0f5d6645cb/sql/core/src/main/scala/org/apache/spark/sql/execution/streaming/runtime/MicroBatchExecution.scala#L1004), [MicroBatchExecution.scala:1453](https://github.com/apache/spark/blob/617618396087429b5627a86ce933bb0f5d6645cb/sql/core/src/main/scala/org/apache/spark/sql/execution/streaming/runtime/MicroBatchExecution.scala#L1453), [statefulOperators.scala:537](https://github.com/apache/spark/blob/617618396087429b5627a86ce933bb0f5d6645cb/sql/core/src/main/scala/org/apache/spark/sql/execution/streaming/operators/stateful/statefulOperators.scala#L537), [statefulOperators.scala:632](https://github.com/apache/spark/blob/617618396087429b5627a86ce933bb0f5d6645cb/sql/core/src/main/scala/org/apache/spark/sql/execution/streaming/operators/stateful/statefulOperators.scala#L632).

These facts support identifying marker-driven advancement as an observable Sail design choice. They do not establish equivalence for removing ended inputs from a watermark minimum, replay under different merge schedules, or one combined watermark as sufficient recovery state. Do not equate Spark's configured watermark delay with a separately verified post-watermark correction window. Those decisions need explicit semantics and focused tests.

## Claims not established by this source verification

- Lease epochs, stale-writer fencing and coordinator checkpoint tags are Sail mechanisms. No such enforcement appears in the inspected Spark change-capture path. The multi-pipeline source tests explicitly execute graphs sequentially, so they do not prove concurrent-writer safety. Source: [AutoCdcScd1MultiPipelineSuite.scala:25](https://github.com/apache/spark/blob/617618396087429b5627a86ce933bb0f5d6645cb/sql/pipelines/src/test/scala/org/apache/spark/sql/pipelines/graph/AutoCdcScd1MultiPipelineSuite.scala#L25).
- A catalog's commit ordering does not by itself establish atomicity across the auxiliary and target tables.
- Broad statements that a stopped Spark streaming table is partly written, or that Sail needs no recovery reconciliation, are not supported by this inspection. Sink and failure-window behavior must be stated specifically.
- The prototypes do not establish general exactly-once recovery, deterministic cross-partition replay, connector-independent source-origin refresh, or complete Spark parity.
