OrcListingReadOptions::resolve is the read boundary. It diagnoses the exact session implementation choice: native is accepted, hive is explicitly unsupported, other values are invalid. The session implementation cannot be overridden by an operation `spark.sql.orc.impl` key. A separate immutable OrcReadSessionModes extension retains implementation and forced-position values; merely storing them does not fail unrelated workloads.

The generated planning options add force_positional_evolution, with only dotted `orc.force.positional.evolution` and the existing Sail `option.*` table-property convention. Session forced mode is overlaid by table/operation layers before validation, so false can disable true. Effective true is explicitly unsupported; automatic all-_col legacy matching is unchanged. Physical OrcReadOptions and wire fields are untouched.

Pinned default V1 Spark source lowercases operation map keys through CaseInsensitiveMap.iterator before Hadoop handoff; generated mode-key matching is therefore explicitly case-insensitive. Session keys remain exact, and runtime `spark.hadoop.*` keys are not stripped. Installed OrcConf bytecode selects the same exact dotted attribute/Hive alias and uses Java Boolean.parseBoolean: only untrimmed case-insensitive true enables forcing; other text is false. The additive parse_java_bool implements that behavior without changing existing boolean parsers.

SparkSession's combined getter captures both immutable default/mode snapshots under its private mutex. The existing narrow DF-write→Spark-mutex synchronization now covers all three exact keys. Both Arc extensions are replaced under the same DF write guard on success or partial mutation failure; the original update error is preserved. Old SessionState and resolved read snapshots remain unchanged. No broad RuntimeConfig transaction or concurrent stress verdict is implied.

Existing B tests retain their assertions through the combined getter. These tests have not been run by the author.

Hadoop startup configuration and variable substitution are not newly implemented. No Spark mode runtime probe was run; the retained source/class audit is not a runtime oracle.
