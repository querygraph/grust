# Documentation publication tooling — prepared, not operated

These private helpers prepare a documentation-only snapshot after root authorizes an exact frozen source map. No snapshot has been copied or staged, and no documentation gate, commit, push, or shared activation has run. The detached destination currently contains the unchanged base `d9df4b0e89b1e4a1838b1b536d05f47ba4f12808`. The combined Sail gate is separate; its unfinished result must not be represented as a completed input.

The source allowlist admits only the eight requested closed review folders, current `RESULTS.md`, and named outer receipts/recipe. It excludes active logging03/followup02 and future pair data. Root must confirm the prospective third outer delivery filename `resource-validation-union-delivery.json` when freezing inputs. PageRank's existing delivery receipt is inside its allowed folder. An optional closed monitor scope requires a separate explicit scope change and review.

The authorization template is intentionally rejected. Root supplies a separate `AUTHORIZED_FROZEN_INPUTS` JSON and its SHA-256, containing every selected path's exact hash, byte count and mode, nonempty closure-receipt assertions (including the combined union), reviewed prose/message, cutoff and exclusions. No directory wildcard copies occur. Ancestor symlinks and paths outside the fixed scope are rejected. Existing tracked evidence is immutable; only `RESULTS.md`, the manifest and an isolated coordination appendix may change.

`common.py` pins the repository's fetch and push destinations, base, branch, raw shared index, selected sources, current results and the read-only inputs `docs/SEM-REVIEW-2.md` and `docs/STREAM-LOSS-STATUS.md`. Shared coordination may grow only by appending bytes after the captured whole-byte prefix (length and SHA-256). Earlier historical insertions are part of that captured prefix. They need not match the base blob. New shared entries are never copied into the candidate.

`prepare_snapshot.py` stages only the authorized candidate paths and regenerates the complete snapshot manifest. `guard.py` requires an independently reviewed frozen tree/manifest, checks source/index/head before and after both documentation gates, and records exact verdicts. Root writes the independent-audit pin only after review. `commit_and_gate.sh` connects gates, commit, and exact-commit gate in one `&&` chain with exclusive log creation. It implies no runtime verdict.

`publish.py` requires the exact gated direct child, both remote refs still at the base, and two fast-forward ancestry checks. It uses one atomic push with explicit compare-and-swap leases for `work/proposal-v5` and `work/sail-graph-review`. It retains intent, command output and uncertain/failure state; it neither retries nor activates shared HEAD.

`activate_shared.py` is a separate, root-only later step. It verifies the already-published SHA and fresh remote refs, builds a private temporary index, acquires the shared index lock, rechecks symbolic HEAD/index and exact source guards, then uses a ref compare-and-swap. It preserves the entire captured shared coordination log and later append-only arrivals using append writes, never replacing it with candidate text. Private backups and last-completed-phase failure receipts remain on partial failure; there is no automatic rollback. Unrelated dirty source bytes remain untouched.

The old reviewed closed2 workflow and activation-v2 audit hashes are in `tooling-preparation.json`. Changes from that workflow are the new base/allowlist, explicit authorization map, shared append-only coordination tolerance, two additional read-only review-input pins, explicit remote URL pinning and selected-path symlink rejection. The old invariant that only the isolated candidate appends to the base coordination blob is preserved.

Nineteen offline controls exercise temporary synthetic local Git data only: unchanged state; accepted coordination suffix; rejected earlier edit/truncation; separate SEM/STREAM mutations; changed results/evidence/index/push destination; selected ancestor symlink; three active-scope rejects; and authorization validation. No production repository mutation or remote command occurs in these controls. AST compilation and shell syntax checks are preparation checks, not publication gates.

Before operation, root and the independent reviewer must review the final helper hashes, then separately review the actual frozen candidate, source exclusions, retained unfavorable/failure evidence and privacy/link/hash checks. Publication must wait for those results. If either remote ref or reviewed source changes, preparation must be explicitly rebased or re-reviewed; these scripts do not overwrite it.
